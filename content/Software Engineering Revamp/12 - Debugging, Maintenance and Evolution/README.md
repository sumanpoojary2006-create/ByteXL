# Unit 12 - Debugging, Maintenance and Evolution

Learning outcome: debug systematically, change legacy code safely and handle production incidents. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 122 | Systematic Debugging | Reproduce, isolate, hypothesise, verify; bisection including git bisect and blame; rubber-duck reasoning |
| 123 | Debugging Tools | Debuggers, breakpoints, watch expressions, profilers, reading stack traces |
| 124 | Logging and Observability | Structured logs, metrics and traces as concepts, what to log and what not to |
| 125 | Incident Management | Triage, hotfix, root-cause analysis, blameless postmortems |
| 126 | Software Maintenance | Corrective, adaptive, perfective, preventive |
| 127 | Laws of Software Evolution | Lehman's laws, ageing software, why maintenance dominates lifetime cost |
| 128 | Program Comprehension and Reverse Engineering | Reading unfamiliar code, call graphs, recovering design from code |
| 129 | Legacy Systems and Re-engineering | Rewrite vs refactor vs wrap, migration strategies, risks of big-bang rewrites; strangler approach, branch by abstraction and automated codemods |
| 130 | Change Impact Analysis | Dependency tracing, change estimation, regression risk |
| 131 | Software Reuse | Libraries, components, frameworks, inner source, costs of reuse |
| 132 | Software Deprecation | Communicating breaking changes, sunset plans, long-term support |
| 133 | Post-Incident Analysis | Post-incident reviews, near-miss analysis, turning lessons into engineering changes |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
