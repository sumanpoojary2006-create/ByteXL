# Unit 10 - Modern Testing Practices

Learning outcome: apply TDD, property-based testing and fuzzing, and judge test suite quality. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 101 | Test-Driven Development | Red-green-refactor, design feedback from tests, when TDD helps and when it does not |
| 102 | Behaviour-Driven Development | Given-When-Then, shared language between product and engineering |
| 103 | Property-Based Testing | Properties vs examples, generators, shrinking failing inputs |
| 104 | Mutation Testing | Mutants, mutation score, finding weak tests |
| 105 | Fuzzing | Random and coverage-guided input generation, crashes and sanitizers, fuzzing parsers |
| 106 | API and Contract Testing | Testing service boundaries, consumer-driven contracts, schema checks |
| 107 | End-to-End Test Automation | Browser automation, locators, test stability, cost vs value |
| 108 | Test Flakiness and Non-Determinism | Time, randomness, concurrency and shared state as causes, quarantine and fix strategies |
| 109 | Test Automation Strategy | Test data management, maintainable suites, parallel runs, what to automate |
| 110 | Exploratory Testing | Charters, heuristics, developer ownership of quality, shift-left |
| 111 | Testing Machine Learning Systems | Evaluation sets, metamorphic testing, regression of model behaviour, probabilistic acceptance |
| 112 | Testing in Production | Canary releases, feature-flag rollouts, monitoring as a test signal, conceptual only |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
