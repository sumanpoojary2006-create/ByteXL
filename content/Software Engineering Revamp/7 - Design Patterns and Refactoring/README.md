# Unit 7 - Design Patterns and Refactoring

Learning outcome: apply common design patterns, recognise code smells and refactor safely. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 68 | Introduction to Design Patterns | Pattern vs idiom vs anti-pattern, problem-context-solution, over-engineering; short survey of Composite, Bridge, Flyweight, Iterator, Visitor and Chain of Responsibility |
| 69 | Factory Patterns | Factory Method and Abstract Factory, decoupling creation from use, product families |
| 70 | Builder, Singleton and Prototype | Step-wise construction, controlled instances, why global state is risky |
| 71 | Structural Patterns | Adapter, Facade, Decorator and Proxy; wrapping and delegation, interface translation |
| 72 | Strategy, State and Template Method | Swapping algorithms, state-dependent behaviour, fixed skeleton with hooks |
| 73 | Observer, Command and Mediator | Event notification, requests as objects, undo, reducing direct dependencies |
| 74 | Patterns in Modern Frameworks | Dependency injection, repository, middleware, functional alternatives to classic patterns |
| 75 | Code Smells and Anti-patterns | Long method, god class, feature envy, shotgun surgery, cargo-cult design |
| 76 | Refactoring Techniques | Extract and move method, parameter objects, replacing conditionals with polymorphism, working under a test safety net |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
