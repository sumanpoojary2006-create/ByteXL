# Unit 2 - Software Process Models and Agile

Learning outcome: compare classical and agile process models and tailor one to a team and project. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 08 | Waterfall Model | Sequential phases, strengths, why it fails on changing requirements |
| 09 | V-Model | Verification vs validation, test levels paired to design levels |
| 10 | Incremental and Iterative Development | Increments, iterations, early feedback, delivery in slices |
| 11 | Prototyping and Evolutionary Models | Throwaway vs evolutionary prototypes, risks of prototype-to-product |
| 12 | Spiral Model | Risk analysis cycles, when risk-driven planning pays off |
| 13 | Agile Values and Principles | Manifesto, working software, responding to change, common misconceptions |
| 14 | Scrum Framework | Roles, events, artefacts, sprint planning, definition of done |
| 15 | Kanban and Lean Development | Flow, WIP limits, waste, cycle time |
| 16 | Extreme Programming Practices | Pair programming, collective ownership, small releases, continuous integration |
| 17 | Process Selection and Tailoring | Team size, risk, regulation, hybrid approaches |
| 18 | Scaling Agile and Distributed Development | SAFe and LeSS at overview level, remote and cross-timezone work |
| 19 | DevOps in the Software Process | Dev and ops collaboration as culture and feedback loop, not tooling |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief. The Kanban lesson's board image is specified as a ticket moving through To Do, In Progress, In Review and Done.
