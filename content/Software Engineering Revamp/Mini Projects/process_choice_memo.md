## Background

Three teams in the same college start work in the same month. One is building a mark-entry system for the examination office, whose rules are fixed by the university. One is building a campus events app that nobody has asked for yet. One is building a fee-payment integration that must be correct before a single rupee moves. Each team asks the same question, "which process should we follow?", and the wrong answer is expensive. The events team that plans every detail up front builds the wrong app slowly. The fee team that improvises builds a fast mistake.

Choosing a process is a judgement, not a preference. This project makes you defend that judgement in writing, using the evidence a team actually has at the start.

## What You Will Build

A two-page process choice memo that recommends a process model for each of three projects, with the reasons, the risks of the choice and the signals that would make the team change its mind.

## Learning Objectives

By the end of this project, you will be able to:
- Compare plan-driven, iterative and agile processes against the facts of a project
- Match the stability of requirements, the cost of failure and the availability of the customer to a process
- State the weakness of your own recommendation
- Define the trigger that should make a team switch process

**Difficulty:** Beginner · **Estimated time:** 2 hours

## Starting Material

| | Project A: Mark Entry | Project B: Events App | Project C: Fee Payment |
|---|---|---|---|
| Who the customer is | Examination office, available weekly | Student council, available daily but unsure | Finance office, available monthly |
| How stable the requirements are | Fixed by university regulation | Unknown, will change after first use | Mostly fixed, a few bank-driven changes |
| Cost of a defect in production | Wrong marks published | A confusing screen | Money charged twice |
| Deadline | Fixed: before the results date | Flexible | Fixed: start of the next term |
| Team | 6 students, new to each other | 4 students, work together often | 5 students, one has done payments before |

## Tasks

### Task 1: Read the Facts

1. For each project, underline the one fact in the table that matters most for the choice of process.
2. Write one sentence per project explaining what that fact does to the plan.

### Task 2: Recommend a Process

1. For each project, pick one of: a plan-driven process, an iterative process, or an agile framework. A hybrid is allowed only if you state exactly which parts follow which approach.
2. Write a short paragraph per project giving three reasons, each tied to a row of the table.
3. Compare your recommendations in a three-row table with the columns Project, Process, Main reason.

Expected result: the three projects do not all receive the same answer, and no reason is a general claim such as "agile is modern".

### Task 3: Defend and Hedge

1. For each recommendation, write the single biggest weakness of the chosen process in that setting.
2. Name one mitigation that does not require changing the process.
3. Name one observable signal, for example "requirements changed three times in a month", that should trigger a review of the choice.

**Answer these questions after completing all tasks:**
- Which row of the table pulled hardest against your recommendation for Project C, and how did you resolve it?
- A teammate says all three projects should use the same process "for consistency". Which cost of consistency would you point to?
- Project B's customer is unsure what they want. How does your process turn that uncertainty into information?
