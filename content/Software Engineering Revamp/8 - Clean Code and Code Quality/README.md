# Unit 8 - Clean Code and Code Quality

Learning outcome: write maintainable code, review changes and manage dependencies and documentation. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 77 | Code Readability | Naming, small functions, comments that earn their place |
| 78 | Coding Standards and Linting | Automating consistency, ending style debates |
| 79 | Defensive Programming and Error Handling | Input checking, fail fast, exceptions vs result types, meaningful errors |
| 80 | Code Review | What to look for, giving and receiving feedback, review checklists, pull-request workflow, small PRs, required reviews and code owners |
| 81 | Pair Programming | Driver and navigator, when it pays off, remote pairing |
| 82 | Technical Debt | Deliberate vs accidental debt, interest, repayment strategies |
| 83 | Code Quality Metrics | Cyclomatic and cognitive complexity, duplication, maintainability index, tool-reported issues |
| 84 | Software Documentation | READMEs, docstrings, API docs, docs-as-code |
| 85 | Dependency Management | Evaluating libraries, upgrade habits, vendoring, abandoned packages |
| 86 | Performance Engineering | Measure first, profiling, avoiding premature optimisation, algorithmic wins vs micro-tuning |
| 87 | Working with Existing Codebases | Reading code, tracing execution, learning conventions, making a first contribution |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
