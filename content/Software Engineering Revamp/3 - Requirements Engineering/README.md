# Unit 3 - Requirements Engineering

Learning outcome: elicit, specify, prioritise and validate testable requirements, and manage changes to them. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 20 | Challenges in Requirements Engineering | Ambiguity, missing stakeholders, moving targets, cost of late discovery |
| 21 | Types of Requirements | Functional, non-functional, constraints, domain and business rules |
| 22 | Requirements Elicitation | Interviews, surveys, observation, workshops, document analysis |
| 23 | User Research and Product Discovery | Personas, jobs-to-be-done, user journeys, problem vs solution framing |
| 24 | User Stories and Acceptance Criteria | Story format, INVEST, Given-When-Then scenarios |
| 25 | Use Cases and Scenarios | Actors, main and alternate flows, preconditions and postconditions |
| 26 | Requirements Analysis and Prioritisation | Conflict resolution, MoSCoW, Kano, RICE; MVP, success metrics and experiments |
| 27 | Software Requirements Specification | IEEE 29148 structure, qualities of a good SRS, lightweight alternatives |
| 28 | Non-Functional Requirements | Making performance, security and usability measurable and testable |
| 29 | Requirements Validation | Reviews, prototypes, walkthroughs, testability checks |
| 30 | Requirements Management and Traceability | Change control, versioning, traceability matrix, scope creep |
| 31 | Requirements for AI-Enabled Systems | Accuracy thresholds, uncertainty, fallbacks, fairness and human oversight |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
