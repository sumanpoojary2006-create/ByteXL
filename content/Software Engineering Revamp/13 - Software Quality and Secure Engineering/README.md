# Unit 13 - Software Quality and Secure Engineering

Learning outcome: apply quality assurance, reliability and secure-development practices to find common vulnerabilities. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 134 | Software Quality Models | McCall, Boehm, ISO 25010 quality characteristics |
| 135 | Software Quality Assurance | Reviews, walkthroughs, inspections, audits |
| 136 | Standards and Process Maturity | ISO 9001, CMMI levels, Six Sigma overview, how services firms use them |
| 137 | Software Metrics and Measurement | Product vs process metrics, Goal-Question-Metric, avoiding vanity metrics |
| 138 | Reliability and Availability | Failure intensity, MTBF and MTTR, reliability growth models at overview level |
| 139 | Safety-Critical Software | Hazard analysis, fault trees, regulated domains such as aviation, automotive and medical |
| 140 | Accessibility | WCAG principles, semantic markup, testing with assistive tools |
| 141 | Secure Development Life Cycle | Security requirements, shift-left, secure design reviews |
| 142 | Common Software Vulnerabilities | OWASP Top 10, injection, broken authentication, memory-safety bugs |
| 143 | Threat Modelling | STRIDE, data-flow based threat analysis, attack trees |
| 144 | Secure Coding Practices | Input validation, output encoding, least privilege, safe handling of secrets |
| 145 | Software Supply Chain Security | Dependency risk, SBOMs, signed artefacts, typosquatting, lessons from Log4Shell |
| 146 | Privacy Engineering and Compliance | Data minimisation, consent, India's DPDP Act and GDPR basics |
| 147 | Resilience Patterns | Timeouts, retries, idempotency, graceful degradation as application-level practices |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief. Topic 146 is an engineer's overview of the laws and not legal advice.
