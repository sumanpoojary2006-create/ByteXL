# Unit 14 - Verification and Program Analysis

Learning outcome: specify intended behaviour, verify code with types and analysis tools, and reason about correctness. Source: `Course Blueprint for Software Engineering.xlsx`, sheet `Syllabus`.

| # | Topic | Concepts |
| --- | --- | --- |
| 148 | Specifications and Design by Contract | Preconditions, postconditions, class invariants, contracts vs tests |
| 149 | Assertions and Runtime Checks | Assert placement, enabling in production, fail-fast behaviour |
| 150 | Type Systems and Verification | Static vs dynamic typing, null safety, algebraic data types, ownership in Rust as a case |
| 151 | Static Analysis | Data-flow analysis intuition, false positives, linters and analysers in CI |
| 152 | Dynamic Analysis | Sanitizers, profilers, coverage tools, runtime monitoring |
| 153 | Program Correctness | Hoare triples, loop invariants, weakest-precondition intuition |
| 154 | Model Checking | Alloy and TLA+ at introductory level, where industry applies them |
| 155 | Verification and Validation Planning | V&V activities by phase, independent V&V, choosing the right assurance level |

This unit is conceptual: it has no code snippets. Worked examples are given as tables and prose. Each image is introduced by a `Visual:` comment that records its brief.
