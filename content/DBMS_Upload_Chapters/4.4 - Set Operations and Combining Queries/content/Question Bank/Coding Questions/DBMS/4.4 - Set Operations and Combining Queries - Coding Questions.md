# Set Operations and Combining Queries — Coding Question Bank

Dialect: **PostgreSQL**. Every query in this bank has been executed against a live PostgreSQL 16 instance; the `Output` shown for each question is the actual result — including one question where the "buggy" query genuinely throws a PostgreSQL error, reproduced verbatim.

**Question Types used in this bank:**
- **Write the Query** — a problem statement, a schema, and you write the query.
- **Bug Hunt** — a query someone already wrote is shown along with its (wrong) output; find and fix the mistake.
- **Predict the Output** — a query is already written; state exactly what it returns before checking the answer.
- **Compare & Justify** — two or more approaches are plausible; write the better one and explain why.
- **Reverse Engineering** — you're shown the data and the target result; work out the query that produces it.
- **Decision-Making** — a concrete symptom is shown; diagnose the cause and recommend a fix.

## Q1. One Combined Donor List

**Topic Tag:** UNION and UNION ALL
**Difficulty:** Easy
**Type:** Write the Query
**Skill Focus:** Summarize

**Problem Statement**

An alumni association ran two separate donation campaigns. Devraj Sen donated to both. For a single thank-you mailing list, each donor should appear only once, no matter how many campaigns they gave to.

**Table: `campaign_a_donors`**

| Column | Type | Description |
|---|---|---|
| `donor_name` | VARCHAR(60) | Donor's name |

**Table: `campaign_b_donors`**

| Column | Type | Description |
|---|---|---|
| `donor_name` | VARCHAR(60) | Donor's name |

Write a query that returns every distinct donor name across both campaigns, sorted alphabetically.

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE campaign_a_donors (donor_name VARCHAR(60));
CREATE TABLE campaign_b_donors (donor_name VARCHAR(60));

INSERT INTO campaign_a_donors VALUES ('Meher Kapadia'), ('Devraj Sen'), ('Anita Fernandes');
INSERT INTO campaign_b_donors VALUES ('Devraj Sen'), ('Kunal Rege');
```

**Output**

```
+-----------------+
|   donor_name    |
+-----------------+
| Anita Fernandes |
| Devraj Sen      |
| Kunal Rege      |
| Meher Kapadia   |
+-----------------+
```

**Solution Query**

```sql
SELECT donor_name FROM campaign_a_donors
UNION
SELECT donor_name FROM campaign_b_donors
ORDER BY donor_name;
```

*Devraj Sen appears in both source tables but only once in the result — `UNION` removes duplicate rows from the combined set automatically.*

## Q3. Deduplicated or Not

**Topic Tag:** UNION and UNION ALL
**Difficulty:** Medium
**Type:** Predict the Output
**Skill Focus:** Analyse (UNION vs UNION ALL row count)

**Problem Statement**

Rakesh Iyer attended two separate training sessions. Before running both a `UNION` and a `UNION ALL` version of the combined attendee list, predict how many rows each version returns.

**Table: `training_session1`**

| Column | Type | Description |
|---|---|---|
| `employee_name` | VARCHAR(60) | Employee's name |

**Table: `training_session2`**

| Column | Type | Description |
|---|---|---|
| `employee_name` | VARCHAR(60) | Employee's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE training_session1 (employee_name VARCHAR(60));
CREATE TABLE training_session2 (employee_name VARCHAR(60));

INSERT INTO training_session1 VALUES ('Rakesh Iyer'), ('Simran Kaur');
INSERT INTO training_session2 VALUES ('Rakesh Iyer'), ('Aditya Menon');
```

**Queries to Analyze**

```sql
SELECT employee_name FROM training_session1 UNION SELECT employee_name FROM training_session2;
SELECT employee_name FROM training_session1 UNION ALL SELECT employee_name FROM training_session2;
```

**Your Task:** How many rows does each version return, and does Rakesh Iyer appear once or twice in each?

**Answer**

```
UNION:
+---------------+
| employee_name |
+---------------+
| Rakesh Iyer   |
| Aditya Menon  |
| Simran Kaur   |
+---------------+
(3 rows)

UNION ALL:
+---------------+
| employee_name |
+---------------+
| Rakesh Iyer   |
| Simran Kaur   |
| Rakesh Iyer   |
| Aditya Menon  |
+---------------+
(4 rows)
```

**Why:** Both source tables together have 4 rows total, and Rakesh Iyer's name appears in both. `UNION` treats the combined result as a *set* — no duplicate rows allowed — so his two appearances collapse into one, leaving 3 distinct names. `UNION ALL` performs no such deduplication; it's a straightforward concatenation of both result sets, so all 4 original rows survive, Rakesh Iyer included twice.

## Q4. A UNION with Uneven Columns

**Topic Tag:** UNION and UNION ALL
**Difficulty:** Medium
**Type:** Bug Hunt
**Skill Focus:** Debug (mismatched column count)

**Problem Statement**

Two online forms collected respondent data — one form asked for an email address, the other didn't. Someone tried to combine both into a single list and the query fails outright.

**Table: `form_responses_a`**

| Column | Type | Description |
|---|---|---|
| `respondent_name` | VARCHAR(60) | Respondent's name |
| `email` | VARCHAR(80) | Respondent's email |

**Table: `form_responses_b`**

| Column | Type | Description |
|---|---|---|
| `respondent_name` | VARCHAR(60) | Respondent's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE form_responses_a (respondent_name VARCHAR(60), email VARCHAR(80));
CREATE TABLE form_responses_b (respondent_name VARCHAR(60));

INSERT INTO form_responses_a VALUES ('Zoya Ahmed', 'zoya.a@mail.com');
INSERT INTO form_responses_b VALUES ('Aditya Menon');
```

**Buggy Query (as submitted)**

```sql
SELECT respondent_name, email FROM form_responses_a
UNION
SELECT respondent_name FROM form_responses_b;
```

**Buggy Output**

```
ERROR:  each UNION query must have the same number of columns
LINE 3: SELECT respondent_name FROM form_responses_b;
               ^
```

**What's Wrong:** `UNION` stacks rows from two `SELECT`s into one result, which only makes sense if both `SELECT`s produce the *same number of columns*, in the same positional order. The first query selects 2 columns; the second selects only 1 — PostgreSQL has no way to line those up, so it refuses to run rather than guess which column is "missing."

**Solution Query (Fixed)**

```sql
SELECT respondent_name, email FROM form_responses_a
UNION
SELECT respondent_name, NULL AS email FROM form_responses_b
ORDER BY respondent_name;
```

**Fixed Output**

```
+------------------+-----------------+
| respondent_name  |      email      |
+------------------+-----------------+
| Aditya Menon     | ¤NULL¤          |
| Zoya Ahmed       | zoya.a@mail.com |
+------------------+-----------------+
```

*Adding an explicit `NULL AS email` to the second `SELECT` gives both sides matching column counts, letting the form-B respondent slot into the combined list with an empty email rather than blocking the whole query.*

## Q7. INTERSECT Ignores Repeats on One Side

**Topic Tag:** INTERSECT and EXCEPT
**Difficulty:** Medium
**Type:** Predict the Output
**Skill Focus:** Analyse (set semantics with duplicates)

**Problem Statement**

A survey was sent out in two batches. Ira Bhagat's name was accidentally entered twice in the first batch's response sheet. Before running an `INTERSECT` to find respondents common to both batches, predict whether Ira Bhagat's duplicate entry causes her to appear twice in the result.

**Table: `survey_batch1`**

| Column | Type | Description |
|---|---|---|
| `respondent_name` | VARCHAR(60) | Respondent's name |

**Table: `survey_batch2`**

| Column | Type | Description |
|---|---|---|
| `respondent_name` | VARCHAR(60) | Respondent's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE survey_batch1 (respondent_name VARCHAR(60));
CREATE TABLE survey_batch2 (respondent_name VARCHAR(60));

INSERT INTO survey_batch1 VALUES ('Ira Bhagat'), ('Ira Bhagat'), ('Yash Purohit');
INSERT INTO survey_batch2 VALUES ('Ira Bhagat'), ('Naisha Verma');
```

**Query to Analyze**

```sql
SELECT respondent_name FROM survey_batch1
INTERSECT

```

**Your Task:** Does Ira Bhagat's name appear once or twice in the result?

**Answer**

```
+------------------+
| respondent_name  |
+------------------+

+------------------+

```

## Q9. Student and Major, Matched Up

**Topic Tag:** When to Use Set Operations vs. Joins
**Difficulty:** Medium
**Type:** Write the Query
**Skill Focus:** Decision-making (choosing JOIN)

**Problem Statement**

A university wants each student's name shown alongside their major's full name — the major names live in a separate lookup table. This calls for matching related columns from two tables side by side, not stacking similar rows into one list.

**Table: `majors`**

| Column | Type | Description |
|---|---|---|
| `major_id` | INTEGER | Unique identifier (PK) |
| `major_name` | VARCHAR(60) | Major's full name |

**Table: `students_major`**

| Column | Type | Description |
|---|---|---|
| `student_name` | VARCHAR(60) | Student's name |
| `major_id` | INTEGER | References `majors.major_id` |

Write a query that returns `student_name` and `major_name` for every student.

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE majors (major_id INTEGER PRIMARY KEY, major_name VARCHAR(60));
CREATE TABLE students_major (student_name VARCHAR(60), major_id INTEGER);

INSERT INTO majors (major_id, major_name) VALUES (1, 'Computer Science'), (2, 'Economics');
INSERT INTO students_major (student_name, major_id) VALUES ('Ojas Pradhan', 1), ('Kiara Mehndi', 2);
```

**Output**

```
+---------------+-------------------+
| student_name  |    major_name     |
+---------------+-------------------+
| Kiara Mehndi  | Economics         |
| Ojas Pradhan  | Computer Science  |
+---------------+-------------------+
```

**Solution Query**

```sql
SELECT s.student_name, m.major_name
FROM students_major s
INNER JOIN majors m ON s.major_id = m.major_id
ORDER BY s.student_name;
```

*A `UNION` would be the wrong tool entirely — it stacks similarly-shaped rows from two sources into one taller list, but here each student needs their major's name attached as an additional column on the same row, which is exactly what a `JOIN` does and a set operation cannot.*

## Q10. One Combined Applicant List

**Topic Tag:** When to Use Set Operations vs. Joins
**Difficulty:** Medium
**Type:** Compare & Justify
**Skill Focus:** Decision-making (choosing UNION)

**Problem Statement**

A hiring team sources candidates from employee referrals and a public job board. Nitin Kapoor happened to apply through both channels. For a single "all applicants" review list, he should appear once, and there's no per-applicant data from one source that needs to be matched up against data from the other — just two lists of names that need combining.

**Table: `applicants_referral`**

| Column | Type | Description |
|---|---|---|
| `applicant_name` | VARCHAR(60) | Applicant's name |

**Table: `applicants_jobboard`**

| Column | Type | Description |
|---|---|---|
| `applicant_name` | VARCHAR(60) | Applicant's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE applicants_referral (applicant_name VARCHAR(60));
CREATE TABLE applicants_jobboard (applicant_name VARCHAR(60));

INSERT INTO applicants_referral VALUES ('Nitin Kapoor'), ('Bhavna Iyer');
INSERT INTO applicants_jobboard VALUES ('Waseem Akhtar'), ('Nitin Kapoor');
```

**Your Task:** Write the query, and explain why a `JOIN` would be the wrong tool for this specific list, unlike Q9.

**Solution Query**

```sql
SELECT applicant_name FROM applicants_referral
UNION
SELECT applicant_name FROM applicants_jobboard
ORDER BY applicant_name;
```

**Output**

```
+----------------+
| applicant_name |
+----------------+
| Bhavna Iyer    |
| Nitin Kapoor   |
| Waseem Akhtar  |
+----------------+
```

**Justification:** The deciding question is always: are these two tables describing *the same kind of thing* that should be stacked into one longer list (`UNION`), or *two different, related things* that should be matched side by side into wider rows (`JOIN`)? Here, both tables hold nothing but applicant names — the same "kind of thing" from two different sources — so `UNION` is correct, and it also solves the deduplication problem for free (Nitin Kapoor collapses to one row). A `JOIN` would instead try to *match* referral applicants to job-board applicants row-by-row on some shared column, which isn't the goal at all — the team wants a merged roster, not a pairing.

## Q14. Columns in the Wrong Order

**Topic Tag:** UNION and UNION ALL
**Difficulty:** Medium
**Type:** Bug Hunt
**Skill Focus:** Debug (positional column mismatch)

**Problem Statement**

Two volunteer shift sheets record the same two facts — volunteer name and assigned task — but one sheet's columns were entered in the opposite order. Combining them with `UNION ALL` runs without any error, but the combined list has names and tasks swapped for half the rows.

**Table: `shift_morning`**

| Column | Type | Description |
|---|---|---|
| `volunteer_name` | VARCHAR(60) | Volunteer's name |
| `task` | VARCHAR(40) | Assigned task |

**Table: `shift_evening`**

| Column | Type | Description |
|---|---|---|
| `task` | VARCHAR(40) | Assigned task |
| `volunteer_name` | VARCHAR(60) | Volunteer's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE shift_morning (volunteer_name VARCHAR(60), task VARCHAR(40));
CREATE TABLE shift_evening (task VARCHAR(40), volunteer_name VARCHAR(60));

INSERT INTO shift_morning VALUES ('Farida Qureshi', 'Registration Desk');
INSERT INTO shift_evening VALUES ('Cleanup Crew', 'Milind Oak');
```

**Buggy Query (as submitted)**

```sql
SELECT volunteer_name, task FROM shift_morning
UNION ALL
SELECT task, volunteer_name FROM shift_evening;
```

**Buggy Output**

```
+----------------+--------------------+
| volunteer_name |        task        |
+----------------+--------------------+
| Farida Qureshi | Registration Desk  |
| Cleanup Crew   | Milind Oak         |
+----------------+--------------------+
(the second row has "Cleanup Crew" sitting in the volunteer_name column, and "Milind Oak" sitting in task)
```

**What's Wrong:** `UNION` (and `UNION ALL`) match columns *by position*, not by name — the first column of every `SELECT` becomes the first column of the result, regardless of what that column is actually called in each source table. `shift_evening` happens to store `task` before `volunteer_name`, so selecting `task, volunteer_name` from it (matching its own column order) actually feeds "task" values into the result's first (name) position and vice versa. There's no error because both columns are the same data type (`VARCHAR`) — PostgreSQL has no way to know the *meaning* is swapped.

**Solution Query (Fixed)**

```sql
SELECT volunteer_name, task FROM shift_morning
UNION ALL
SELECT volunteer_name, task FROM shift_evening
ORDER BY volunteer_name;
```

**Fixed Output**

```
+----------------+--------------------+
| volunteer_name |        task        |
+----------------+--------------------+
| Farida Qureshi | Registration Desk  |
| Milind Oak     | Cleanup Crew       |
+----------------+--------------------+
```

*Each `SELECT`'s column list needs to be written to match the result's intended column order, not the source table's own internal column order — explicitly naming `volunteer_name, task` in both queries keeps the meaning aligned regardless of how each table happens to store its columns.*

**Type:** Reverse Engineering
**Skill Focus:** Reconstruct (choosing the right operator)

**Problem Statement**

A support desk logs tickets by category in separate tables. Sana Iqbal shows up in both the billing and technical ticket logs. Someone has already pulled the list of customers who have filed *both* kinds of tickets — work out which operator produces this from the two source tables.

**Table: `billing_tickets`**

| Column | Type | Description |
|---|---|---|
| `customer_name` | VARCHAR(60) | Customer's name |

**Table: `technical_tickets`**

| Column | Type | Description |
|---|---|---|
| `customer_name` | VARCHAR(60) | Customer's name |

**Dataset Creation Query (Backend)**

```sql
CREATE TABLE billing_tickets (customer_name VARCHAR(60));
CREATE TABLE technical_tickets (customer_name VARCHAR(60));

INSERT INTO billing_tickets VALUES ('Rohan Mehta'), ('Sana Iqbal');
INSERT INTO technical_tickets VALUES ('Sana Iqbal'), ('Farhan Ali');
```

**Target Output**

```
+----------------+
| customer_name  |
+----------------+
| Sana Iqbal     |
+----------------+
```

**Your Task:** Write the query that produces exactly this result.

**Solution Query**

```sql
SELECT customer_name FROM billing_tickets
INTERSECT
SELECT customer_name FROM technical_tickets;
```

*The target output has only one row, containing exactly the name common to both source tables — a `UNION` would have returned three names (everyone from either table), and a `JOIN` on `customer_name` would have produced the same one matching row here, but only by coincidence of this particular data; `INTERSECT` is the operator whose actual definition matches the question being asked.*
